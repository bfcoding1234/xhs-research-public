# 测试与验收指南

## 1. 文档定位

本文对应传统软件开发中的测试策略、测试计划入口和验收职责说明。具体自动化用例以测试代码为事实来源；产品行为以 [PRODUCT_RULES.md](./PRODUCT_RULES.md) 和已确认方案为准；质量门禁以 [ENGINEERING_GUARDRAILS.md](./ENGINEERING_GUARDRAILS.md) 与根 [AGENTS.md](../AGENTS.md) 为准。

历史的完整测试方案和测试用例包见 [2026-08-01 产品交付快照](./product-deliverables/09-测试方案与测试用例.md)，只用于参考，不替代当前测试代码。

## 2. 角色分工

| 角色 | 责任 |
| --- | --- |
| 产品经理 / 业务负责人 | 明确业务验收标准、关键场景、范围和主观体验要求 |
| 前后端研发 | 为纯函数、组件、接口、事务和回归缺陷补充相邻自动化测试 |
| 测试 / 质量负责人 | 设计跨模块、失败、边界、兼容、恢复和真实用户流程测试 |
| AI 开发协作者 | 完成可自动执行的检查、构建、接口与真实运行验收，不把可发现问题留给用户 |
| 用户 | 只终验登录、验证码、主观产品取舍和约定保留的体验事项 |

## 3. 测试层级与入口

| 层级 | 主要位置 | 重点 |
| --- | --- | --- |
| 前端纯函数与契约 | `web/src/**/*.test.ts` | 格式化、排序、偏好迁移、Query Key 和 API 契约 |
| 前端组件与页面 | `web/src/**/*.test.tsx`、`*.ui.test.tsx` | 加载、空、失败、交互、选择、弹窗和无障碍语义 |
| 后端单元与集成 | `tests/test_*.py` | 数据语义、事务、状态、迁移、接口和 Provider 适配 |
| 架构和文档 | `scripts/validate_architecture_docs.py` | 文档链接、常驻规则预算和专题导航完整性 |
| 构建产物 | `web/dist/` | 源码与生产资源同步、真实服务资源清单 |
| 真实运行流程 | 回环 HTTP 服务与浏览器 | 新代码已加载、真实数据库、核心接口和用户主流程 |

需求到相邻测试的具体导航见 [CODEMAP.md](./CODEMAP.md)。

## 4. 标准验证门禁

后端与跨层：

```bash
python3 -m compileall -q scripts/workbench/xhs_research scripts/xhs_research.py
python3 -m unittest discover -s tests
```

前端：

```bash
cd scripts/workbench/web
npm run typecheck
npm run lint
npm run lint:antd
npm test
npm run build
```

文档：

```bash
python3 scripts/validate_architecture_docs.py
```

先运行相邻测试获得快速反馈，再按改动风险运行完整门禁。前端构建完成后仍需确认 Python 服务实际返回新的 `dist/index.html` 和资源清单。

## 5. 测试用例模板

高风险功能的方案或测试文档至少记录：

| 项目 | 内容 |
| --- | --- |
| 用例 ID 与目标 | 对应业务规则、风险或历史回归 |
| 前置条件 | 数据、任务状态、登录态、配置和权限 |
| 操作步骤 | 用户或接口执行的最短可重复步骤 |
| 预期结果 | 页面、接口、任务、数据库和事件的可观察结果 |
| 失败与边界 | 空数据、非法输入、并发、超时、取消、恢复和重试 |
| 自动化位置 | 测试文件和测试名称；不能自动化时说明原因 |
| 验收层级 | 单元、组件、接口、集成、真实浏览器或用户体验 |

## 6. 变更影响

- 页面和交互变化：更新组件测试、页面状态测试和必要的真实浏览器验收。
- API 契约变化：同步前端类型、接口测试、错误测试和缓存失效测试。
- 数据模型变化：覆盖新库 Schema、旧库迁移、索引、事务和真实数据兼容。
- 任务与并发变化：覆盖排队、运行、等待登录、取消、失败、部分成功、恢复、重试和服务重启。
- Provider 或 Codex 变化：覆盖结构化输出、登录阻塞、降级、超时、取消和子进程清理。
- 列表变化：覆盖筛选、排序、分页、跨页选择、偏好恢复、宽表和表格/卡片一致性。

自动化测试能约束的事实优先写进测试，而不是只写成文字规则。
