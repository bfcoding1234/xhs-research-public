# 列表页规范

> **适用范围**：任何需要浏览、查询、比较和处理一组同类对象的 Web 页面或详情页内的列表区块。
>
> **使用目标**：本规范可复制到其他项目，作为 AI 设计、实现和验收列表页时的共同约束。它只定义通用的结构和交互原则；字段、权限、业务操作、默认排序与数据口径由各项目自己的产品规则决定。

## 1. 使用方法

开发或修改列表页时，先按本规范确定页面骨架，再补充项目的业务规则。若有冲突，优先级为：**本次明确需求 → 项目业务规则与设计系统 → 本规范 → 既有实现**。

- 共同规则（控制区、状态、排序、分页、选择、宽表、无障碍与验收）只在本规范维护一次。
- 对象专属规则（字段、状态含义、排序依据、可执行操作、权限和文案）写在相应的产品文档中，不反向塞进通用列表组件。
- 同一类对象出现在多个入口时，默认将“改该对象列表”视为通用需求；只有明确指定入口才做局部差异。
- 不是所有列表都需要卡片视图、批量选择、筛选或新建按钮。业务不需要时直接省略，不能为形式统一而添加无效控件。

## 2. 列表页要完成的工作

用户应能在一个连续流程中完成：**确认当前范围 → 查询并缩小范围 → 比较对象 → 选择对象（如需要）→ 执行业务操作 → 确认结果或继续浏览**。

页面要把这些步骤清楚分层，避免把搜索、筛选、视图切换、批量操作和表格配置混杂在同一排，导致用户无法判断哪个操作会影响什么。

## 3. 标准页面结构

```text
面包屑：首页 / 上级对象 / 当前列表（按导航层级决定是否显示）
页面标题与说明                                      [页面级低频操作]
├─ 当前对象内容与对象级操作（可选）
└─ 列表主体
   ├─ 范围摘要：对象名、筛选后数量 / 总数、刷新状态（可选）
   ├─ 控制区
   │  ├─ 查询：搜索、高频筛选、更多筛选（可选）
   │  ├─ 视图：表格 / 卡片切换（仅支持双视图时）
   │  ├─ 操作：新建、刷新、批量业务操作
   │  └─ 配置：密度、列设置、全屏（仅表格视图）
   ├─ 内容区：表格或卡片网格
   ├─ 状态区：加载、失败、空状态、操作反馈
   └─ 分页：总量、页码、每页数量（仅需要时）
```

### 3.1 面包屑、标题、对象内容与页面级操作

- 页面存在可返回的业务层级时显示面包屑，层级使用用户能理解的对象名称；不可点击的当前页位于末级。全局一级页面或固定左侧导航已足以说明位置时可以省略。
- 标题直接说明对象或任务域；简短说明交代数据范围或用户能在此完成的工作。
- 标题下方可以展示当前对象的摘要内容和对象级操作，例如项目名称、状态、负责人、更新时间、编辑或归档。没有明确对象上下文时直接省略，不能为凑结构创建空卡片。
- 只作用整个页面、且不依赖当前筛选或选中项的低频动作可放在标题区域，例如全局帮助或页面级设置。
- 仅作用当前列表范围的搜索、筛选、刷新、新建和批量动作优先放入列表工具栏。
- 同一可见区域同时最多一个主按钮；其余动作降为次级按钮、链接或“更多”。
- 有 Tab 时，Tab 表示数据域或对象分组；工具栏和操作必须随当前 Tab 切换，不能展示对当前内容无效的能力。

### 3.2 范围摘要

- 摘要应说明正在查看什么、范围有多大。推荐“筛选后 N / 总计 M”或“共 N 项 · M 项进行中”。
- 总量未知时只显示可确定的数量，不能伪造分母或把当前页数量当总量。
- 后台刷新时，若已有上次成功结果，在摘要附近显示轻量刷新状态；不要清空内容区或使用阻断浏览的整页遮罩。

### 3.3 控制区：查询 / 视图 / 操作 / 配置

| 分组 | 包含内容 | 交互要求 |
| --- | --- | --- |
| 查询 | 搜索、高频筛选、更多筛选 | 位于最前；搜索占位文本说明可搜索的对象或字段。 |
| 视图 | 表格/卡片切换、卡片排序 | 仅在支持多个视图时出现；切换不丢失当前条件。 |
| 操作 | 新建、刷新、导入、导出、批量操作 | 文案和位置稳定；可用性用禁用态、说明或确认表达。 |
| 配置 | 密度、列显示、列顺序、固定列、全屏 | 只属于表格视图，不在卡片视图展示。 |

- 只有一两个简洁筛选时可直接展示；条件较多时，首层只留搜索和高频筛选，其余收进显示已生效数量的“更多筛选（N）”。
- “更多筛选”中的变化先暂存；用户点击“确定”才应用，点击“重置”回到该列表默认筛选。计数只统计非默认条件。
- 搜索可即时生效。搜索、筛选、排序或每页数量变化后，应回到第 1 页，或由服务端纠正到有效页码。
- 按选择数量变化的状态使用固定宽度区域，例如“已选 N 项”；不要把数量拼到业务按钮文字中，避免选择后页面抖动。
- 批量按钮维持稳定文案，未选择或选择不合法时禁用；通过可访问名称或邻近说明传达选择数与不可用原因。

## 4. 内容呈现

### 4.1 表格视图

表格适合多字段比较和高密度浏览，通常是数据型列表的首选。

- 每列有稳定标识、明确标题和合适宽度；长文本截断时应能通过悬停、展开或详情查看完整内容。
- 每个具体列表在页面详细设计中维护字段表，至少声明字段 ID、标题、数据来源、默认顺序、默认宽度、展示格式，以及是否允许显示、排序、筛选和固定。通用规范不替业务对象决定字段。
- 支持批量选择时，选择列固定在左侧；否则固定主标识列。操作列固定在右侧，使横向滚动时仍能识别对象和完成操作。
- 列很多时只允许表格内部横向滚动，页面本身不能被撑出横向滚动条。布局容器要允许其收缩，例如 Grid 轨道用 `minmax(0, 1fr)`，相关 Grid/Flex 子项设 `min-width: 0`、`max-width: 100%`。
- 可排序字段在表头提供明确反馈。排序行为应经过受控状态管理，且默认顺序必须稳定、可解释。
- 单字段筛选或排序在后端和组件能力允许时优先从对应列头进入；同一条件不能同时以两个互不一致的状态存在于列头和顶部筛选区。高频跨字段条件仍放在查询区。
- 用户可配置显示列、顺序或固定状态时，配置按“同构列表类型”持久化，并提供恢复默认配置的入口。
- 不把框架默认的选中提示条当作批量操作入口；选择状态和批量操作由控制区统一表达。

### 4.2 卡片视图

卡片不应只是把表格列换行排列。仅当对象具备视觉信息、卡片有助于快速扫读，且关键操作仍然明确时使用。

- 表格与卡片共享同一份筛选、排序、分页和选择状态；不能各自产生不同结果集。
- 每张卡片突出对象身份、1～3 个决策所需指标，以及必要的单项操作；不要复制所有表格字段。
- 每个支持卡片视图的具体列表必须在页面详细设计中声明卡片内容：主标题与辅助身份、封面或头像（如有）、状态、1～3 个核心指标、补充信息、主要操作、“更多”操作和选择控件。没有清晰决策价值时不提供卡片视图。
- 支持批量选择时，卡片必须显式提供逐项选择、当前页全选、已选计数和排序入口，不能依赖被隐藏的表头。
- 同一对象在表格与卡片中的点击语义一致。站内详情在当前页打开；外部资源在新标签页打开；无有效链接则禁用。
- 网格应从单列逐步扩展到多列。小屏优先保证信息与操作可读，不能只依靠缩小字体硬塞内容。

### 4.3 单项与危险操作

- 操作列只保留高频、低风险且容易理解的动作；低频操作放入“更多”。
- 删除、解绑、取消、覆盖等不可逆或可能造成损失的动作，必须说明影响并二次确认。
- 需要配置、会启动后台工作或影响多项数据的操作，先进入确认/配置界面；成功后刷新对应数据，并按业务规则保留或清除选择。

## 5. 数据、排序、分页与选择

### 5.1 数据职责

- 大数据量、可筛选或可排序的列表使用服务端分页、筛选和排序。服务端必须先在完整筛选范围内排序，再返回当前页；不能下载全部数据后只在浏览器中筛选。
- 前端以当前页、每页数量、筛选与排序请求数据，并使用服务端返回的总量渲染分页。页大小上限由后端能力和用户浏览成本共同决定。
- 服务端数据只保留一个可信来源。后台刷新保留上一次成功结果；写操作成功后只刷新受影响的数据，不维护互相可能不一致的页面副本。

### 5.2 排序与偏好

- 排序是受控状态，持久化合法的“字段 + 方向”组合；刷新后恢复，过期或非法值回退到默认值。
- 不同列表类型的排序偏好彼此隔离；同一对象的表格与卡片共享排序状态。
- 默认排序、并列时的稳定次级排序、允许排序的字段均由业务规则明示。排序循环通常为升序 → 降序 → 默认顺序。

### 5.3 分页

- 仅在数据量需要分段时显示分页，包含总量、上一页/下一页、页码和每页数量；数据跨越较多页时提供快速跳页。小数据集可以省略跳页，但不能省略用户已需要的页码切换和每页数量选择。
- 筛选、搜索、排序和页大小变化不得导致用户停留在不存在的页。
- 视图切换、刷新或后台重新请求不得丢失仍然有效的页码、筛选、排序与页大小。

### 5.4 批量选择

- 选择以稳定对象 ID 保存，跨分页、表格/卡片切换和刷新保留。
- “全选”只作用当前页内可选项目，并在已有选择集合上增删，不能覆盖其他页的选择。
- 只有用户明确取消、批量操作成功，或对象已离开业务范围时清除相应选择。
- 不可操作行的选择控件应禁用，并在需要时解释原因；提交批量操作前只传递仍然合法的对象 ID。

### 5.5 浏览器偏好持久化

以下配置按同构列表类型保存在本地浏览器中，刷新或重新进入页面后恢复：

- 表格或卡片视图选择；
- 表格显示列、列顺序和左右固定列；
- 合法的排序字段和方向；
- 每页展示数量。

实现要求：

- 使用稳定的列表类型 ID 和配置版本隔离，例如 `xhs-research:list:<list-type>:v1`；不要按临时路由参数为每个项目重复保存同一套表格结构。
- 读取后先校验字段、方向、固定位置、页大小和视图是否仍受支持；过期或非法配置只回退对应默认值，不能导致页面不可用。
- 同一对象在全局、项目或作者入口使用同构列表时共享结构偏好；确有字段或操作差异时使用不同列表类型 ID。
- 提供“恢复默认”入口，并只清除当前列表类型的偏好。
- 当前页码默认不作为长期偏好保存，避免重新进入时落到已不存在的页面；筛选条件是否保存由具体产品规则决定。
- 偏好只保存展示配置，不保存 Token、Cookie、原始业务数据或其他敏感信息。

## 6. 状态与反馈

| 情况 | 推荐表现 | 必须保留 |
| --- | --- | --- |
| 首次加载 | 内容区加载态，避免整页无反馈 | 标题和已知页面框架。 |
| 后台刷新 | 轻量刷新状态 | 上次成功数据、筛选和选择。 |
| 首次请求失败 | 可理解的错误说明与重试入口 | 标题和页面上下文。 |
| 后台刷新失败 | 警告提示与“立即重试” | 上次成功数据，不能用错误替换列表。 |
| 初始为空 | 空状态说明“还没有…”，必要时提供唯一创建操作 | 标题与适用的创建入口。 |
| 筛选无结果 | 说明“没有符合当前条件的…”，提供清除/调整路径 | 当前筛选条件。 |
| 操作进行中 | 对应操作显示 loading，必要时禁用冲突操作 | 列表及不相关操作。 |

- 成功提示不能替代可见的数据更新：完成后计数、行数据和对象状态应与结果一致。
- 错误文案用用户能理解的语言说明发生了什么和下一步能做什么；不要只显示技术错误或错误码。

## 7. 无障碍与响应式

- 所有按钮、图标按钮、搜索框、筛选器、复选框和外链都有可理解的可访问名称；图标不能是唯一的信息来源。
- 通过键盘能完成搜索、筛选、选择、打开详情和执行主要操作；焦点顺序与视觉阅读顺序一致，弹窗可关闭且焦点可返回触发点。
- 颜色只作辅助状态，不单独表达成功、错误、禁用或选中。
- 小屏先保证主标识、核心指标和关键操作；将低频列折叠、改为详情或使用卡片，不在页面层面制造横向溢出。

## 8. 使用 Ant Design 时的落地约定（可选）

使用 Ant Design 的项目，在新增或重组列表页前，应通过本地文档或 CLI 查询当前版本的设计语言和实际组件 API，不凭记忆拼写属性。

- 优先使用 `Table` / `ProTable`、`Pagination`、`Empty`、`Spin`、`Select`、`Dropdown` 等系统组件及其设计 token；不要为单页发明脱离系统的控件样式。
- 一个页面只保留一个 primary 按钮；其他操作使用 default、link 或 dropdown，避免同一区域出现多个主操作竞争注意力。
- `Pagination` 使用受控的当前页、页大小、总量与变更回调；`Empty` 区分初始为空和筛选无结果；`Spin` 或表格 loading 用于内容区加载。
- 使用设计 token 管理颜色、间距、圆角、阴影和动效，避免硬编码零散样式；遵循 4px 间距网格和语义色，状态信息不只依赖颜色。
- 表格头部、按钮、输入与状态反馈遵循当前主题的密度与层级，避免无意义的嵌套 Card 和装饰性阴影。

## 9. 交付验收清单

- [ ] 标题、范围摘要、控制区和内容区职责清楚；同一可见区域至多一个主操作。
- [ ] 搜索、筛选、排序和页大小变化后页码正确；服务端列表先排序再分页。
- [ ] 支持多视图时，表格与卡片共享查询条件、排序、分页和选择；支持批量操作时选择跨页保留。
- [ ] 选择数不会改变业务按钮的位置或宽度；批量操作只处理合法选中项。
- [ ] 宽表固定主标识/选择列与操作列，并确认页面不产生横向溢出、表格内部可横向滚动。
- [ ] 首次加载、后台刷新、首次失败、后台失败、初始为空、筛选为空和操作进行中均有恰当表现。
- [ ] 排序和列配置的本地偏好合法、稳定、可恢复默认；不同列表类型互不污染。
- [ ] 表格/卡片视图、列顺序、固定列、排序和每页数量刷新后正确恢复；过期配置能安全回退。
- [ ] 键盘操作、焦点管理、可访问名称、禁用态、确认弹窗和内外链行为符合操作风险与语义。
- [ ] 完成与改动相称的类型检查、静态检查、自动化测试和真实页面验收；以常用桌面宽度和小屏宽度检查信息层级与布局稳定性。

## 10. 不在本规范内的内容

本规范暂不规定详情页、创建/编辑表单、仪表盘、设置页、报告页和官网。后续为这些页面建立规范时，应复用这里的状态反馈、无障碍、操作风险和设计系统约定，避免对同一事实重复定义。
