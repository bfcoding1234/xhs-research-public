# xhs-research 工程约束

## 文档用途

本文记录实现层面的高风险边界和已验证约束。根据任务涉及的模块只读取相关小节；系统关系见 [ARCHITECTURE.md](./ARCHITECTURE.md)，页面/API/服务/依赖事实从 [详细设计索引](./details/README.md) 进入，具体文件和测试入口见 [CODEMAP.md](./CODEMAP.md)，历史原因见 [LEARNED_RULES_HISTORY.md](./history/LEARNED_RULES_HISTORY.md)。

## 一、HTTP、安全与静态资源

- `server.py` 的写请求入口只读取一次请求体，并将解析后的 `payload` 传给路由分支；任何分支不得再次从 socket 调用 `_body()`。
- HTTP handler 只负责输入解析、校验、路由和响应。跨数据库与执行器的业务动作放入 `ResearchApplication` 或明确服务对象；持久化统一通过 `Database`。
- 服务只监听回环地址并校验回环 `Host`。浏览器写请求必须来自可信本机 `Origin`；CLI 可以不发送 `Origin`。写请求必须是顶层对象 JSON，并遵循统一请求体大小限制。
- `/media/` 只返回数据库登记、位于规范数据目录且真实内容识别为图片或视频的文件；MIME 取自内容识别，不能信任扩展名。数据库、WAL、SHM、锁、日志、临时文件和未登记文件不得返回。
- 未知 `/api/*` 返回 JSON 404，不回退前端应用壳。前端静态路由回退和 API 错误处理必须保持隔离。
- Cookie、Token、验证码、完整账号凭据和隐私信息不得进入任务输入、结果、事件、日志或数据库；测试夹具也不得使用真实凭据。

## 二、数据库、关系与迁移

- `schema.sql` 是新库定义，`Database.initialize()` 负责旧库兼容迁移。表、列、索引或约束变化必须同时覆盖两者，并用旧库升级测试和新库测试验收。
- 作者和帖子是全局主数据，项目关系使用关联表或引用；任何“关联到项目”实现不得复制实体。关系解除和项目删除必须在事务中保持全局实体不变。
- 新任务、报告占位、输入快照和活跃任务唯一约束必须在同一数据库事务中完成，不能先创建部分业务记录再异步补写关键关系。
- 任务输入写入 `input_json`，可恢复进度和结果写入 `result_json` 与 `task_events`。新任务需要冻结的设置、Provider 路由、Prompt 和目标 ID 清单必须在创建时快照。
- GET 请求不得通过逐文件存在性检查、哈希或读取媒体计算衍生状态；文件大小、内容哈希、OCR/图片理解完成状态等在写入或一次性迁移时持久化。
- 开发数据发布按作者 ID、帖子 `note_id` 和项目 `slug` 合并，先预览再确认并留下审计记录；不得删除稳定数据或迁移活跃任务。

## 三、任务、并发、取消与恢复

- 可离开页面后继续的生成和批处理使用持久化任务。创建时冻结输入和目标，复用排队、运行、等待登录、取消、失败、重试和服务恢复，不依赖前端页面生命周期。
- 大范围更新创建一个后端任务，在任务内固定目标清单、分批执行并持久化进度。批次大小、作者间等待、批次间等待和连续失败阈值可配置；外部 CLI 的进程内限速不能替代工作台跨指令节流。
- 已入库实体的定向补全直接按稳定 ID 或原文地址读取；不得为了命中目标重新搜索或重新发现。
- 任务取消、服务停止和超时必须向 Runner、采集 CLI 和 Codex 子进程传播。进程组先正常终止，超过宽限期再强制清理；任务结束后不得遗留子进程。
- `waiting_login` 保留已完成来源与进度，允许用户验证后继续和受控自动检测。服务重启后的恢复语义以任务模型为准，不得悄悄新建替代任务。
- 新建采集入口只公开 `keyword` 和 `author`。`mixed` 仅用于历史数据、兼容 API 和历史任务重跑；修改共享表单、模型或迁移时可以继续兼容，但不得重新暴露为可创建选项。
- 图片理解、OCR、报告和关键词建议分别保存实际任务类型或处理方式；不同方式不得复用完成状态。空 OCR 结果也要记录处理完成。

## 四、报告与 Codex 增强能力

- 关键词建议、图片理解和报告任务调用 Codex 时隔离无关项目规则、插件、Hooks 和工具，并使用明确的工作目录、推理强度、超时、取消与诊断策略。
- 大模型报告的生成中版本在任务创建事务内预留。成功原位提交版本；失败、取消、中断或恢复失败在一致性事务中清理占位，`latest_report_id` 只指向完成版本。
- 复杂报告在一个 `ai_report` 任务内固定证据快照，按字符预算分批、受控并发、复用缓存并串行合成；不得由前端创建多个内部子任务。
- 分批结构化输出进入缓存和最终汇总前校验证据 ID 范围。发现越界时用允许 ID、错误字段和原始结果执行一次受约束修复，修复后再次严格校验；不得静默删除或接受非法引用。
- Prompt 模板与用户要求在任务创建时保存完整内容和哈希。缓存键包含模板哈希、分析要求和证据范围；配置变化只影响新任务，重试沿用原任务快照。
- 报告上下文配置必须在服务端校验作者/帖子至少一个来源开启；动态帖子比例向上取整且有帖子时至少取一篇，20% 模式最多 20 篇。帖子字段开关只改变证据字段，不得混入未选择的正文、OCR 或大模型理解文本；历史 `context_detail` 任务按原配置重试。
- 数据摘要只能读取同一 SQLite 快照并做确定性描述统计，不调用外部 Provider。手动与数据任务完成后的自动摘要必须复用同一构建器和 schema；自动摘要与任务完成状态原子提交。大模型报告和数据摘要使用独立版本，不把当前实时数据补写到旧快照。
- 文字报告来源使用 `sources` 复选快照并至少包含 `data_summary` 或 `current_detail`。摘要来源必须校验同范围和完成状态并冻结完整结构化内容与哈希；两者同时启用时，Prompt 与证据结构都必须声明“摘要统计、明细举例”，不得把明细统计混成第二套口径。
- HTML 演示稿 Provider 只返回受 schema 限制的 JSON，不接收或保存模型生成的 HTML/CSS/脚本。服务端渲染器必须转义全部模型文本、禁止远程资源，列表接口不回传完整 HTML；HTML 读取接口使用严格 CSP、`nosniff` 和 `no-store`。演示稿任务与占位原子创建，完成提交、取消和失败清理沿用报告任务的一致性边界。

## 五、外部 CLI 与结构化输出

- 采集任务只调用业务能力，`CapabilityRegistry` 根据任务创建时的路由快照选择默认指令并在失败后按顺序降级。不得把 Provider 判断散落到前端、任务模型或 Runner 其他分支。
- 能力路由必须区分普通失败与人工阻塞。每个候选指令的登录或验证错误先由 Runner 保持 `waiting_login`；定时探测仍是人工阻塞时不得前进，人工恢复信号触发的同指令重试失败后才计为该候选失败并进入下一指令。任务事件应能区分普通失败与人工处理后的降级。
- 通过 `xiaohongshu-cli` 写入前强制刷新所选浏览器 Cookie，并校验非访客且账号信息完整。失败统一转换为可恢复登录状态，禁止继续读取或写入。
- 搜索适配器构造帖子 URL 或写库前校验模型类型、帖子卡片结构和稳定 ID。非帖子推荐卡和含 URL 分隔符的 ID 被过滤后不计入发现数量。
- 外部模型或 CLI 的结构化输出 Schema 必须先用最小 Schema 做真实调用，再增加约束；只采用目标接口明确支持或真实验证通过的关键字。静态 JSON 校验和单元测试不能代替真实 CLI 验收。
- 用户可见错误保持简短，完整 stdout/stderr 尾部、尝试次数、输入规模和耗时进入内部诊断；不得在错误文本中泄露凭据。
- CLI 提示升级时先确认原命令解析到的实际可执行文件。项目本地 CLI 更新项目依赖和锁文件；只有实际使用全局 CLI 时才全局升级，最后重跑原命令验证。

## 六、前端状态、复用与 Umi

- 服务端状态统一由 React Query 管理。只对活跃任务轮询，轮询保留上一次成功数据；操作成功后失效或移除准确的 query key，不维护并行的页面业务状态副本。
- 共享列表、详情内容、筛选、排序和批量选择优先放在 `features`；页面只提供路由参数和明确的上下文差异。个人入口复用作者详情能力。
- 详情抽屉和独立详情页复用同一核心内容组件。帖子媒体、OCR、图片理解和作者统计口径不得各维护一套。
- `src/app.tsx` 只导出 Umi 支持的运行时配置与钩子；辅助组件保持私有或移到独立文件。修改该入口后必须真实加载页面并检查控制台。
- 前端源码改动完成后依次运行 typecheck、lint、`lint:antd`、test 和 build；服务只托管 `dist/`，因此必须核对 `dist/index.html`、资源清单和真实 HTTP 返回均已更新。
- `package-lock.json` 和 `dist/` 随源码同步；`node_modules/` 与 `src/.umi/` 不进入版本控制。

## 七、Ant Design、表格与布局

- 修改或新增 Ant Design 页面前，使用项目本地 CLI 查询当前 `design.md`、组件 API 和 Token；完成后同时运行静态合规检查和真实页面审查。
- 同页只保留一个主操作，查询、视图、业务操作和表格配置分层。长内容优先使用章节和分隔线，避免无意义的多层 Card。
- 宽表显式设置横向滚动宽度，固定选择或主标识列和操作列。其 Grid 轨道使用 `minmax(0, 1fr)`，承载链上的 Grid/Flex 子项和表格包装器使用 `min-width: 0`、`max-width: 100%`，确保只在表格内部滚动。
- 真实页面验收同时确认页面 `scrollWidth` 不超过视口、表格仍可横向滚动，以及选择前后按钮坐标和宽高没有动态位移。
- ProTable 列设置使用稳定唯一的 `columnsState.persistenceKey` 与本地存储，同构列表共享、异构列表隔离；排序和分页偏好同样使用受控状态和合法值校验。

## 八、性能与读取边界

- 详情首屏统计使用索引覆盖的轻量摘要接口。全局列表、项目明细和候选选择一律服务端分页、筛选和排序，不得先下载完整实体数组再由浏览器筛选。
- 列表接口 `page_size` 上限为 100。活跃任务轮询任务与轻量摘要，任务结束后再刷新明细，避免每次进度更新重新加载大列表。
- 多阶段报告、图片处理和大范围更新在后端编排；前端不循环请求模拟批次，不暴露内部并发、重试和分片参数。
- 长配置页 sticky 目录、页尾激活和滚动高亮必须基于真实滚动容器和文档高度，不能默认假设 `documentElement` 或布局 `main`。

## 九、测试与真实运行时验收

- 回归行为能由测试表达时必须落测试，历史事故说明不能替代自动检查。接口和数据库修改至少覆盖成功、校验失败、取消/恢复、事务回滚和旧数据兼容中相关场景。
- 超时、取消和子进程清理测试使用低启动开销假进程或显式就绪信号；行为超时与环境首次启动延迟不得共用过紧窗口。
- Python 服务、接口、数据查询或运行时配置修改后，交付前先检查目标服务身份、数据目录和活跃任务。无活跃任务才重启；`already_running` 不证明加载了新代码。
- 重启后核对真实 `/api/health`、相关业务接口、数据一致性和核心前端交互。采集路由改动还要核对能力目录、路由快照、任务事件和最终 `capability_usage`。
- 纯静态前端改动可以不重启 Python 服务，但必须通过真实服务重新加载并确认使用了新资源；无法确认是否触及已加载 Python 模块时按后端改动处理。
- 文档链接、路由、模块职责和测试归属由 `scripts/validate_architecture_docs.py` 校验；系统边界变化同步更新架构与代码地图。

## 十、分支、worktree 与数据环境

- 未经用户明确要求不创建多 worktree。并行分支合并前先核对主分支当前路由、可见入口和业务边界，只引入本任务范围；历史兼容类型不得重新暴露。
- 合并与主分支验收完成后，检查所有临时 worktree，处理有价值的未提交源码，停止不再需要的进程，删除已合并且干净的 worktree 和临时分支，并用 Git 状态复核。
- 主 worktree 与 linked 开发 worktree 使用独立端口和数据目录。发布数据必须显式、可预览、可确认、可审计；普通开发和测试不得直接读写稳定数据目录。
