# xhs-research 产品行为规则

## 文档用途

本文是工作台术语、业务范围、默认行为和跨页面交互的权威产品规范。只按当前任务读取相关小节；页面空间布局从 [页面详细设计](./details/pages.md) 进入，同类页面的形成规则见 [页面规范](./page-specs/README.md)，系统与数据边界另见 [ARCHITECTURE.md](./ARCHITECTURE.md)。如果本文与代码或测试不一致，按根 [AGENTS.md](../AGENTS.md) 的冲突处理规则核对并同步修正。

## 一、术语与默认作用范围

- 全局入口和标题统一使用“个人”“作者”“项目”“任务中心”，不使用“我的项目”“调研项目”。“个人”是用户选定的一位全局作者的特殊详情入口，不维护另一套作者、帖子或报告模型。
- 用户说“作者详情”时，默认同时覆盖普通作者详情和个人详情；明确说“只改个人”时才只作用于个人入口。
- 用户说“作者列表”时，默认覆盖全局作者列表及项目等附属作者列表的通用能力；明确限定某一入口时才做局部差异。
- 用户说“帖子列表”时，默认覆盖全局、项目、普通作者和个人四类入口的通用能力；入口专属需求使用明确参数或局部扩展实现。
- 用户说“这个页面”时必须先确认当前路由或页面身份，不能只依赖上一轮讨论推断。

## 二、项目与全局实体

- 项目代表可持续积累的调研主题。新建页面只收集名称和可选说明并使用当前默认项目类型，不自动采集；名称和说明可编辑，但保持 `slug`、内部调研类型、配置、关键词、关系、任务和报告不变。
- 作者和帖子按稳定 ID 保存在全局主数据中，项目只保存关系。关键词搜索命中的帖子及其作者分别关联项目；作者主页采集的帖子只进入全局库，必须由用户手动关联才进入项目。
- 项目作者关系来源可以叠加，展示为“任务主动添加”“手动关联”“关键词帖子作者”。项目作者来源筛选默认“全部”，首次进入不得隐式过滤。
- 取消项目关系只删除当前项目关系，不删除全局实体。取消作者关系时，如果该作者仍有项目帖子，先展示每位作者的项目帖子数量并二次确认；确认后同时移除该作者及其当前项目相关帖子关系。
- 更新已关联实体的资料或详情不得新增、覆盖或伪造关系来源。只有项目帖子原本没有作者、更新后首次识别出作者，且项目中尚无该作者关系时，才补建 `post_author`。
- 所有项目删除入口必须先确认任务状态安全，再要求逐字输入完整项目名称；名称完全一致才允许删除。删除项目只清理项目关系和报告，保留全局主数据和已结束任务记录。

## 三、导航与详情页层级

- 工作台默认业务入口为“个人”；主导航顺序为“个人 → 作者 → 项目 → 任务中心”，帖子和后台配置收进“更多”。侧栏和页脚不展示本地服务、技术栈、存储方式或版权年份等运行说明。
- 根路由 `/` 使用独立官网布局，不渲染工作台 ProLayout、侧栏或 Ant Design 页面结构；工作台从 `/my-projects` 等业务路由进入。官网 CTA 只站内跳转，不复制业务状态或接口逻辑。
- 实体详情页顺序为“标题与操作 → 全局信息或必要跨 Tab 指标 → Tab → Tab 内容”。能归属单个 Tab 的数量直接显示在 Tab 名称中，不再复制为顶部指标卡。
- 同页 Tab 切换不显示面包屑；进入帖子详情、任务详情等更深层级才显示。共享详情路由必须保留进入上下文，返回、取消后跳转和重试后的详情跳转回到同一上下文。
- 列表中的站内实体详情默认当前页跳转；原文、作者主页等外部链接才新开标签页。
- 快速详情抽屉复用完整详情页的核心内容，只由容器控制路由、标题和操作；抽屉内保留当前上下文，并提供当前页进入完整详情的入口。

## 四、作者列表与作者详情

- 所有作者列表在过滤和分页前默认按全局粉丝数降序，粉丝相同时按稳定作者名称排序；表头显示默认降序，用户选择的其他排序仍生效。
- 作者列表提供“列表 / 卡片”切换并默认卡片视图。列表和卡片都展示 IP 属地；卡片另固定展示头像、名称、简介、粉丝、获赞与收藏，并保留“主页”“详情”操作。
- 单行操作只保留“主页”和“详情”；“主页”新开小红书作者主页，“详情”进入站内详情。“更新基础信息”和“关联项目”不作为单行操作，批量更新和批量关联继续保留。
- 卡片视图必须支持逐项选择、全选当前页、跨页保留选择、已选数量和排序。全局与项目作者列表使用同一套选择状态和批量控件。
- 作者详情核心指标优先展示粉丝、获赞与收藏、帖子覆盖量。帖子覆盖量使用“数据库已存/作者发表总数”；总数未知显示 `已存/—`，不得用已存数补写总数。

## 五、帖子列表与帖子详情

- 帖子列表使用与作者列表一致的紧凑头部、列表/卡片切换、选择状态、排序和业务操作。项目详情 Tab 标题使用“帖子”，不使用“帖子证据”。
- 表格可排序字段在升序、降序和默认顺序间切换；卡片排序与表头共用同一业务排序状态。服务端分页必须先对完整筛选范围排序，再分页。
- 每页数量在所有帖子入口间共享浏览器本地偏好。列表视图点击封面预览大图；卡片视图点击标题或封面进入站内帖子详情。
- 帖子列表与卡片的展示图优先使用已获取的详情首图；没有详情首图时回退到列表封面。详情首图只有远程地址时仍优先展示。
- 帖子操作列使用“原文”，在新标签页打开；无链接时禁用。需要关联项目的入口支持选择、批量“关联到项目”和单行“关联”。作者详情帖子列表继承相同能力。
- “信息完整度”“OCR 识图”“图片理解”在表格相邻展示，筛选区同时提供 OCR 与图片理解状态；OCR 是主筛选，图片理解保留在更多筛选。OCR 使用“待执行 OCR / OCR 已完成 / 其他”：有可用本地图片且未全部处理为待执行，全部本地图片已记录完成时间为已完成，没有可执行本地图片为其他。
- 项目和作者帖子列表的“更多筛选”提供媒体存储状态：“远程图片待下载”表示至少一张正文图片只有原图地址而没有本地文件，“正文图片已本地化”表示正文图片均无待下载项，“无正文图片”表示没有正文图片记录。封面不计入该筛选。
- 项目帖子页将项目全量处理进度收纳在“信息完整度”和“OCR 识图”列标题的点击式注释中：详细信息已完成/待补全，以及 OCR 已完成/待处理/无可处理图片。统计不受当前筛选和分页影响；“查看待补全”“查看待 OCR”清除其他筛选后进入对应缺口列表，“去处理”打开默认 OCR 的补充图片理解窗口。
- 帖子发布时间在列表、详情和报告帖子表格中统一显示：带时区的精确时间转为上海时区 `YYYY-MM-DD HH:mm`；只有日期时保留 `YYYY-MM-DD`，不得伪造时间。
- 帖子详情媒体优先使用本地服务 URL，本地副本缺失或加载失败时回退 `original_url`，并明确标示“已保存本地”或“原图链接”。抽屉和独立详情页共用媒体展示逻辑。
- 帖子详情正文在抽屉和独立详情页中始终完整展示，不按行数截断或提供收起状态，并保留全文复制。
- 全局、项目、普通作者和个人四类帖子列表的单帖操作都提供“补充评论”；只允许单帖发起，用户每次选择 1～20 页后创建独立评论采集任务，不提供批量评论采集。
- 评论任务默认“继续补充”：从帖子上次保存的 cursor 向后读取，每页评论入库与检查点推进同一事务完成。“重新更新”从首页幂等更新近期评论，不回退有效的深度检查点；检查点失效时才用更新结果重建。
- 两次连续评论请求间默认随机等待 1～2 秒，可设 1～60 秒，不使用 CLI 的 `--all`。默认只保存一级评论附带的回复预览；开启楼中楼后串行调用 `sub-comments`，请求预算默认 20 页、可设 1～100 页，达到预算时保留部分结果并明示未完整。
- 帖子详情的“评论”模块展示该帖累计已保存的一级评论与嵌套回复、平台回复数、检查点状态和最近任务；评论列表限定高度并独立滚动，运行中展示已落库页面并自动刷新。除可配置的“补充评论”外，详情内提供“快捷补充评论”，按配置表单默认值直接创建任务，不打开弹窗或成功提示。
- 项目帖子列表中的帖子标题和卡片打开当前页详情抽屉，关闭后保留列表筛选、分页和选择状态；独立详情页继续支持直接访问和来自报告等非列表入口的跳转。
- 项目帖子列表和卡片默认展示关联作者当前粉丝数与项目内实时关注分。关注分以 `总互动 / (粉丝数 + K)` 为主体，再乘以低互动置信系数；`K` 为项目有帖去重作者粉丝中位数且不低于 100，互动平滑值为有效帖子总互动中位数且不低于 1。最终映射为项目内 0～100 百分位，不用于跨项目比较。
- 项目帖子关注分支持服务端升降序：分数始终基于项目全部有效帖子和作者计算，不随当前搜索、筛选或分页改变；先对完整筛选范围排序再分页，无有效分数的帖子置后。列表使用当前数据实时计算，数据摘要冻结生成时快照，两者在数据更新后允许不同但必须使用同一公式。
- 帖子详情更新必须把封面或第一张图片成功落地为可读取图片作为成功条件；直接下载失败时使用媒体下载能力兜底。封面未落地时记录失败且不刷新详情成功时间，正文其他媒体不要求全部下载。
- 已入库帖子的详情补全必须通过帖子主键、`note_id` 或原文地址直接锁定目标。选中模式严格处理所选帖子；范围模式在任务创建时固定 ID 清单，不重新搜索、不复制实体、不改变关系。

## 六、列表与高密度内容的通用交互

- 控制区按“查询 / 视图 / 操作 / 配置”分组，卡片视图再区分“选择 / 排序”。列表上下文内的搜索、筛选、刷新和新建优先放在列表工具栏。
- 筛选较多时首层只保留搜索和高频条件，低频条件收进显示已生效数量的“更多筛选”。弹层内先暂存修改，“确定”应用，“重置”恢复默认；只有一两个条件时不强行折叠。
- 选择状态使用固定宽度“已选 N 位/篇”下拉触发器；取消选择、反选等低频操作放入下拉，业务按钮文案和位置保持稳定。列表视图才显示密度、列配置和全屏。
- 所有分页选择按稳定实体 ID 跨页、跨列表/卡片视图和刷新保留。全选只作用当前页并在已有集合上增删；只有用户主动取消、批量操作成功或实体离开完整业务范围时清理。
- 用户选择的排序按业务入口保存到浏览器本地偏好；刷新后恢复，非法旧值回退默认值，不同入口互不覆盖。
- 开放列设置的 ProTable 使用稳定唯一的本地持久化 key。同构列表共享、异构列表隔离，并提供重置默认列配置。
- 宽表固定左侧选择或主标识列与右侧操作列，横向滚动只发生在表格内部，不得引起页面级横向溢出。
- 长执行轨迹使用固定最大高度内部滚动区，默认最新事件在前，并允许切换最早事件在前；标题区显示事件总数和活跃任务刷新状态。
- 高密度关系图同时提供可审计全景、按业务域视图和当前节点直接上下游逐跳探索。各视图共用同一份节点与关系数据；详情抽屉支持点击外部、显式关闭和 `Escape` 关闭。

## 七、任务创建、展示与生命周期

- 从项目、个人或作者页面创建单任务后显示统一成功弹窗，提供“查看任务详情”和“留在当前页”；“留在当前页”为主操作并在 5 秒后自动执行，只有用户明确选择查看才跳转。批量创建没有唯一详情时提供任务列表入口，不自动跳转。
- 可离开页面继续执行的生成和批处理必须创建持久化任务并冻结输入快照；前端不得循环创建多个内部子任务来模拟一个业务操作。
- 任务中心全局操作只放刷新等跨类型动作。采集、图片理解和报告等类型专属的新建或批量动作放在对应 Tab 或内容工具栏，切换类型后不展示。
- 任务中心按“采集任务 / 图片理解 / 大模型报告 / AI 关键词生成 / 评论采集”分组；新建采集入口只公开关键词和作者两种模式，评论采集只能从具体帖子发起。历史 `mixed` 任务可以查看和按原配置重跑，但不得重新出现在新建选项中。
- 项目总览的活跃任务只展示状态、阶段、进度和详情入口，不直接取消；取消等生命周期操作放在任务详情或项目“任务”Tab 等明确任务上下文。
- 任务详情基于 `input_json` 展示人可读“创建参数”，按任务类型转换业务字段；原始 JSON 可折叠保留。`input_json` 是跨任务类型输入，不得只按采集配置建模。
- 大范围作者或帖子更新由一个可追踪的后端任务固定目标清单并分批执行；批次、等待和失败阈值可配置，进度持久化，支持 `waiting_login` 继续和服务恢复。前端只发起一次任务。

## 八、图片增强与采集数据质量

- 项目、普通作者和个人帖子列表提供“补充图片理解”，处理方式按“OCR 识图 → 大模型理解”排列并默认 OCR；全局帖子列表不提供入口。
- 项目任务只处理项目帖子；作者和个人任务只处理该作者帖子。切换处理方式时，能力状态、可用数、完成数、待处理数和预计数必须同步切换。
- OCR 与大模型理解共用“封面图 / 详情图片”复选范围，至少选择一项并默认只选封面图；详情图片指除 `cover` 外的正文图片和视频封面帧。新任务按范围分别处理，历史未保存范围的任务继续按全部图片执行。
- 图片处理不提供 Provider 切换：OCR 固定使用 RapidOCR，大模型理解固定使用 Codex。能力不可用时在创建前明确提示，不静默切换其他引擎。
- 大模型图片理解的模型、推理强度和调用超时只在“后台配置 → 图片理解”维护；模型选项来自本机 Codex 可见且支持图片输入的模型目录。执行任务窗口不展示这些技术参数，新任务冻结后台当前值，重试沿用原任务快照。
- OCR 与大模型理解分别追踪可用性、结果和完成状态。OCR 即使没有识别出文字也记录已处理，避免重复执行。
- 搜索结果写库前必须区分真实帖子与热搜词等推荐卡片，校验模型类型、帖子结构和 ID；非帖子模型和包含 URL 分隔符的 ID 不计入发现数量，并继续在受控分页内寻找真实帖子。
- 采集 CLI 在写入前验证真实登录态；访客态、失效态和验证要求进入 `waiting_login`，不得把表面成功响应写成有效采集结果，也不得用浏览器通用访问绕过验证。当前采集指令需要人工处理时不得立即降级：受控自动检测仍未通过则继续等待；用户确认处理完成后先重试同一指令一次，成功则继续，仍失败才按路由顺序降级。普通非人工故障仍可立即降级，后备指令遇到人工阻塞时适用同一规则。

## 九、关键词候选与报告

- AI 关键词候选是持久化 `keyword_suggestions` 任务：冻结项目与参考关键词快照，可关闭弹窗后继续、恢复、取消和重试；生成结果只作为候选，用户确认后才写入项目关键词。
- 用户选择的来源决定语义参考；项目全部已有关键词始终用于去重。候选在确认前只属于临时结果，成功重新生成才替换；添加、调整来源和重新生成互斥，项目删除时清理临时缓存。
- 项目、普通作者和个人报告统一分为“数据摘要 / 大模型报告”。数据摘要不调用外部 Provider，只基于同一数据库快照产生可复现描述统计并独立保留版本；建议、规律解释和机会判断只进入大模型报告。
- 数据摘要按“帖子 / 作者”组织，每个模块依次回答数据完善度、业务分布和 Top 对象；字段完善度与帖子详情、OCR、图片理解等处理覆盖分开展示。处理覆盖只读取已有结果，刷新摘要不得触发任何 Provider；OCR 与大模型理解各自只展示封面图、详情图片两行覆盖率，不再展示全部图片行。
- 帖子字段覆盖至少包含标题、正文、发布时间、帖子类型、点赞、收藏和评论；作者字段覆盖至少包含昵称、小红书号、简介、地区、头像、粉丝、关注、获赞与收藏、发布帖子总数及资料获取状态。只展示存在缺失的字段，并以紧凑行显示有效数、总数、缺失数和百分比；数值 `0` 是有效数据而不是缺失。
- 数据摘要的帖子业务趋势按数据跨度使用日、周或月粒度，并可切换发布帖子数、周期去重作者数，以及按帖子发布时间归组的快照累计点赞、收藏和评论；互动缺失值不按 `0` 聚合，真实 `0` 仍计入有效样本。描述统计还包含帖子类型、点赞/收藏/评论长尾分桶、多指标 Top 帖子；项目范围额外包含作者体量、地区、项目贡献分布及多指标 Top 作者。地区取作者 IP 属地，以离线省级块状地图展示全部可识别地区，未知、海外和历史快照中的“其他”在地图外单列；不得调用在线地图服务。缺失值不按 `0` 进入分布；总互动只使用点赞、收藏、评论全部存在的严格完整样本；篇均互动 Top 作者至少需要 3 篇完整样本。
- 项目数据摘要在常规 Top 帖子之前展示“值得关注的帖子”，使用与项目帖子列表相同的平滑关注分公式并冻结本次系数和结果；最多展示 10 条，同时给出帖子互动、作者粉丝、项目帖子数和作者获赞收藏。作者和个人摘要不展示该跨作者模块，schema v1～v5 历史摘要不回填。
- 项目摘要完整展示帖子和作者模块；普通作者和个人摘要的作者模块只展示当前资料与字段完善度，不展示无统计意义的作者分布或 Top 作者。
- 手动生成和项目或作者数据任务成功更新后的自动生成使用同一个结构化摘要构建器；失败、取消或没有成功处理数据的任务不新增版本。版本标明手动或自动触发来源，自动生成不创建额外任务。
- 旧快照缺失字段不得用当前数据补写；旧版 Markdown 摘要继续按历史内容展示，新版本统一使用当前结构化 schema。
- 大模型报告创建时立即预留 `generating` 版本；列表显示但禁用该项，同时保留最近已完成版本可读。成功原位完成，失败、取消、中断或恢复失败删除占位版本；只有存在生成中版本时轮询。
- 大模型报告的数据来源是至少选择一项的复选：可引用同一项目或作者的一份已完成数据摘要、任务启动时的当前明细，或同时引用两者。所选摘要的结构化内容、版本、时间和哈希随任务冻结；同时引用时，摘要是统计数字、趋势和分布的唯一口径，当前明细只补充案例、原文和定性证据，不得重算或覆盖摘要指标。
- 复杂报告的分批、并发、缓存、重试和合成隐藏在单一后台任务内。Web 提供证据概况、标题、补充要求和精确上下文设置：作者与帖子来源至少开启一项；帖子按“20% 且最多 20 篇 / 50% / 100%”动态选样，并独立选择基础信息、正文、OCR 文本和当前有效的大模型理解文本。技术批次参数不向用户暴露。
- 报告提示词和用户要求随任务保存完整快照与哈希；配置变化只影响新任务，重试沿用原快照，缓存键包含模板哈希和本次要求。
- 已完成且正文非空的大模型报告可制作固定主题的 HTML 演示稿。已有演示稿版本必须显示在长篇文字报告正文之前，打开报告即可预览或下载，不得放在正文末尾。演示稿绑定具体文字报告版本，以持久化 `ai_report` 任务生成严格 JSON，再由服务端转义并渲染自包含 16:9 HTML；同一源报告可保留多个版本。本期不生成 `.pptx`，不提供在线编辑、主题选择或自动配图。

## 十、后台配置与官网体验

- 后台配置按“调研与采集 / 能力与处理 / 个人设置 / 系统信息”组织，配置项仍独立保存。
- 桌面端长配置页左侧目录在内容滚动时保持可见；点击平滑定位，手动滚动同步高亮，页尾能激活最后一项。实现前先确认真实滚动容器。
- 新增或重组 Ant Design 页面时，同一页面只保留一个主操作，查询、视图和业务操作分层；长内容优先使用章节和分隔线，避免连续嵌套卡片。验收覆盖常用桌面宽度和真实数据状态。
- 官网和工作台分别验证浏览器标题、双向布局隔离、桌面与移动端页面级横向溢出，并同步构建 `dist/`。
