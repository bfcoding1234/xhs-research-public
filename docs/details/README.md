## 记录粒度

- 页面文档描述用户可见结构和交互，不重复产品规则正文。
- API 文档记录跨前后端契约，不复制服务内部实现。
- 服务文档记录模块职责和协作，不逐函数解释源码。
- 依赖文档记录“能做什么、不能做什么、失败后怎样处理”，不把 Provider 名称写进业务模型。
- 数据库列定义以 `schema.sql` 和兼容迁移为事实来源；文档解释业务语义。

## 维护闭环

新增跨层能力时，至少检查：

```text
用户操作 / 展示
  → 页面与页面规范
  → API 或纯本地行为
  → 应用服务 / TaskRunner / Database
  → 数据表、文件或外部依赖
  → 前端、后端与真实运行测试
```

没有某一层时明确写“无”并说明原因，例如纯本地视图偏好不经过 API，确定性数据摘要不调用外部大模型。
